# Инструкции для агентов ShiftHelper

## Назначение и границы MVP
- ShiftHelper связывает заказчиков и исполнителей краткосрочных подработок.
- Заказчик публикует задание, получает отклики и выбирает одного исполнителя.
- Исполнитель сдаёт работу; заказчик подтверждает результат; стороны оставляют отзывы.
- В MVP входят аккаунты, профиль, каталог, публикация, отклики и личные списки.
- Роль customer или worker выбирается при регистрации и не меняется.
- Оплата происходит напрямую между участниками.
- Платежи, резервирование денег, документы самозанятых, чат и споры вне текущего MVP.
- Не превращай идеи дальнейшего развития в требования без обсуждения.

## Стек и карта проекта
- Backend: Go и Gin; PostgreSQL через pgx; Redis; миграции Goose.
- Frontend: React, TypeScript и Vite; React Router, TanStack Query и React Hook Form.
- Инфраструктура: Docker Compose, nginx, Traefik; проверки в GitHub Actions.
- Версии сверяй с backend/go.mod, frontend/package.json и Dockerfile.
- backend/cmd — точки запуска API, worker и заполнения демоданных.
- backend/internal — обработчики и логика предметных областей.
- backend/migrations — SQL-миграции; backend/migrations.go встраивает их в приложение.
- frontend/src/app — запуск, маршрутизация, сессия через shared и общие стили.
- frontend/src/pages — страницы; widgets — крупные блоки; entities — сущности.
- frontend/src/shared — API, UI, состояние и утилиты.
- docs/openapi.yaml — контракт; frontend/orval.config.ts — генерация клиента.
- infra — Compose, Dockerfile и конфигурация сервисов; swagger — просмотр API.
- scripts — сквозная проверка MVP; .github/workflows/ci.yml — проверки CI.
- Taskfile.yml — команды запуска, миграций, сборки и проверок.

## Начало работы
- Прочитай этот файл, затем инструкции из раздела «Маршрутизация инструкций».
- Проверь git status, текущую ветку и изменения других участников.
- Если существует .codex/context.md, прочитай его как дополнительный локальный контекст. Не публикуй его содержимое. При расхождении фактов проверяй код, Git и актуальную карточку задачи.
- Отсутствие локального контекста не мешает работе.
- Локальная память не подменяет общие командные правила.
- Прочитай карточку задачи, её описание, критерии готовности и зависимости.
- Уточняй существенные противоречия; рутинные решения принимай самостоятельно.
- Определи минимальный объём изменения и подходящие проверки.
- Не меняй функциональность за пределами согласованной задачи.

## Git и совместная разработка
- main — стабильная версия; dev — общая разработка.
- Каждая задача выполняется в feature/... или fix/... от актуальной dev.
- Перед созданием ветки обнови ссылки через git fetch origin --prune.
- При чистой рабочей папке обновляй dev командой git merge --ff-only origin/dev.
- Изменения возвращаются через PR в dev.
- Агент делает коммит и push; создаёт PR только по прямой просьбе.
- Перед коммитом просмотри diff и добавляй только относящиеся к задаче файлы.
- Не затирай, не откатывай и не включай в свой коммит чужие изменения.
- Не выполняй reset --hard, force push и другие разрушительные операции без согласования.
- Не переписывай общую историю ради косметики.
- После подтверждённого слияния удали завершённую ветку локально и на origin.
- Перед удалением проверь слияние; ветки невлитых PR сохраняй.
- После удаления обнови ссылки через git fetch origin --prune.

## YouGile
- Проект ShiftHelper, префикс SHI, доска dev.
- Перед работой прочитай карточку и связанные зависимости.
- Переведи взятую задачу в In progress и укажи согласованного исполнителя.
- Новые карточки оформляй по образцу доски, а не только названием.
- Заполни область, тип, приоритет, сложность, зависимости и исполнителя.
- В описании укажи цель, объём работ и критерии готовности.
- Поддерживай описание и статус актуальными при изменении объёма.
- Проверяй сохранённые изменения повторным чтением карточки.
- Различай готовность реализации, принятие результата и слияние PR.
- Ставь Done и отметку выполнения по фактическому завершению согласованной работы.
- Не утверждай, что код слит, пока это не подтверждено в Git.
- Если YouGile недоступен, сообщи об этом и не утверждай, что карточка обновлена.
- Не записывай токены и личные настройки подключения в общие инструкции.

## Проверки и завершение
- Запускай проверки, соответствующие изменению; команды смотри в технической инструкции.
- Сверяй команды с package.json, Taskfile.yml и CI, если они изменились.
- Проверяй git diff --check и итоговый состав файлов перед коммитом.
- Для документации проверь ссылки, команды и отсутствие личного контекста.
- Для интерфейса проверь затронутые сценарии на компьютере и узком экране.
- Для API и БД проверь права, состояния, ошибки и согласованность контракта.
- Не называй проверки успешными, если они не запускались или завершились ошибкой.
- В итоге кратко укажи изменения, выполненные проверки и существенные ограничения.
- После задачи дай короткое готовое описание PR обычным текстом.
- В описании PR перечисляй только изменения, без тестов, сборки и других проверок.
