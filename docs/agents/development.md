# Технические правила ShiftHelper

Читайте при изменении backend, API, БД, интерфейса или проверок.
Командный процесс описан в корневом AGENTS.md; стиль — в DESIGN.md.

## Backend и контракт
- Схемы запросов, ответов и ошибок задаёт docs/openapi.yaml.
- Orval читает контракт через frontend/orval.config.ts.
- После изменения контракта: npm --prefix frontend run api.
- В коммит включайте согласованные изменения контракта и сгенерированного клиента.
- Клиент находится в frontend/src/shared/api/generated; HTTP-обёртка — рядом в http.ts.
- Денежные суммы API хранит целыми копейками RUB; даты передаются с часовым поясом.
- Задание проходит open → in_progress → awaiting_confirmation → completed.
- Отмена допустима только для open; выбранный исполнитель один.
- Один отклик на пару задание/исполнитель сохраняется навсегда, включая отозванный.
- Сохраняйте существующий порядок проверки прав и состояния; скрытые ресурсы дают 404.
- При мутациях сначала блокируется строка задания FOR UPDATE, затем отклики.
- Не меняйте этот порядок: он защищает от гонок при выборе и завершении работы.
- Отзывы доступны участникам завершённой работы; повторная отправка запрещена.
- Сессия серверная; токен передаётся в HttpOnly cookie, в БД хранится его хеш.
- Не переносите пароли или токены в localStorage, sessionStorage и кеш запросов.
- APP_ORIGIN управляет проверкой источника запросов и защищённой cookie.
- Auth ограничен по IP: 30 входов и 20 регистраций за минуту, отдельные счётчики до Argon2id, включая неверные данные. При 429 смотрите Retry-After; автоматической повторной отправки нет.
- Счётчики локальны одному API и сбрасываются при рестарте; максимум 4096 IP на операцию, истёкшие окна обновляются, при заполнении удаляются истёкшие ключи, новые ключи без места получают 429. Несколько экземпляров API пока не поддерживаются этим ограничителем.
- При прямом запуске TRUSTED_PROXIES по умолчанию пуст: X-Forwarded-For игнорируется. Укажите только IP/CIDR своих прокси, не 0.0.0.0/0.
- Compose доверяет диапазону Docker bridge 172.16.0.0/12; при нестандартной сети задайте TRUSTED_PROXIES по фактическому адресу/подсети прокси. Backend не публикует порт наружу. Traefik не должен работать с forwardedHeaders.insecure=true.
- API через Traefik идёт прямо в backend; nginx при обращении к нему напрямую дополняет X-Forwarded-For адресом соединения. Vite тоже дополняет цепочку: для локального Vite доверяйте только его loopback-адресу в TRUSTED_PROXIES (127.0.0.1,::1), API держите доступным только локально.
- Новые SQL-миграции добавляйте в backend/migrations в формате Goose.
- Учитывайте встроенные миграции из backend/migrations.go и существующие данные.
- Не редактируйте уже применённую миграцию ради изменения схемы.

## Frontend
- Используйте существующие формы, API-функции, SessionProvider и компоненты сущностей.
- Сохраняйте защиту маршрутов по ролям и возврат после входа.
- Изолируйте приватный кеш по пользователю; поздний ответ не должен восстанавливать сессию.
- При мутациях сохраняйте ввод при ошибке и блокируйте повторную отправку.
- Проверяйте загрузку, ошибку, пустой результат и конфликт с обновившимся состоянием.
- Переводите локальные даты в API-формат явно; не меняйте точность денежных сумм.
- Визуальные изменения проверяйте также на узкой ширине без горизонтальной прокрутки.
- Локально установленный Stageshow можно использовать для демонстрационных анимаций.
- Он необязателен: рабочие формы и анимации должны функционировать без установленного навыка.

## Проверки и запуск
Команды ниже выполняются из корня репозитория, если явно не указан другой каталог.
Версия Go задаётся backend/go.mod; frontend CI использует Node.js 24.

- Установка frontend-зависимостей: npm --prefix frontend ci.
- Frontend: npm --prefix frontend run lint (ESLint), npm --prefix frontend run typecheck, npm --prefix frontend run test:ci.
- Форматирование frontend: npm --prefix frontend run format:check; исправление: npm --prefix frontend run format.
- Общие проверки: task lint и task format:check; автоформатирование: task fmt.
- Production-сборка: npm --prefix frontend run build.
- После генерации проверьте diff в frontend/src/shared/api/generated.
- CI повторно генерирует клиент и проверяет отсутствие diff в этой папке.
- В каталоге backend: go test ./..., go vet ./....
- Используйте golangci-lint 2.15.0, как в CI: golangci-lint run --config=../.golangci.yml ./... из backend.
- Проверка Go-формата без записи: golangci-lint fmt --config=../.golangci.yml --diff --diff-colored=false ./... из backend.
- Сборка в backend: go build ./cmd/api ./cmd/worker ./cmd/demo.
- Интеграционные backend-тесты требуют TEST_DATABASE_URL и доступной PostgreSQL.
- CI поднимает PostgreSQL 17; без тестовой БД не объявляйте интеграционные тесты пройденными.
- Подключайте тесты к отдельной БД; не направляйте их на пользовательские данные.
- Сквозной сценарий: bash scripts/check-mvp.sh; требуется Docker Compose.
- Скрипт создаёт отдельный стенд, проверяет сценарий и перезапуск, затем удаляет свои тома.
- Не подменяйте его очистку удалением томов основного проекта.
- Для локального запуска через Task: task up; подготовка окружения описана в Taskfile.yml.
- Без Task сначала подготовьте локальный infra/.env по infra/.env.example.
- Затем: docker compose --env-file infra/.env -f infra/compose.yaml up -d --build --wait.
- Статус: docker compose --env-file infra/.env -f infra/compose.yaml ps.
- Миграции: task migrate:status и task migrate:up; откат согласовывайте отдельно.
- Режим Vite и адреса прокси описаны в frontend/README.md.
- Для правок документации достаточно проверки ссылок, команд, diff и приватности.
- Полный сценарий нужен при изменении взаимодействия сервисов или основного потока MVP.
- Не повторяйте дорогие проверки без новых изменений, ошибок или нерешённых сомнений.
- Фактический набор проверок и их результат укажите в отчёте отдельно от описания PR.
